# 術語

| 術語 | 意思 |
|---|---|
| 看板（board） | PTT 的討論區，例 `Gossiping`、`Stock`、`Tech_Job`、`HatePolitics`；`Gossiping` 需要 `over18` cookie |
| 文章檔名 | PTT 文章 URL 的檔名，例 `M.1792340682.A.08F`；`M.` 後面是發文的 Unix 時間 |
| `post_id` | `<board>.<文章檔名>`，例 `Gossiping.M.1759730000.A.1B2`，全系統唯一鍵 |
| 推／噓／→ | 推文的三種類型：推（正面）、噓（負面）、箭頭（中性回覆）；`comments.type` 用 CHECK 約束 |
| 推噓數 | 推 − 噓；列表頁顯示「爆」代表 ≥ 100、`X1`～`XX` 代表負數 |
| 爆文 | 推文數很多、正在快速增加的文章；熱度偵測的主要目標 |
| 爭議度 | 噓 ÷（推＋噓）；推＋噓 < 10 時不顯示（開發規格 7.23） |
| 共鳴度 | 推文總數（推＋噓＋→，設計文件 15.6） |
| 年齡分級 | 依文章發文時間決定重爬頻率，越新重爬越頻繁（設計文件 4.2） |
| `recrawl_min_push` | 文章滿 1 小時後，推文總數（推＋噓＋→）低於該看板門檻就停止重爬；控制 Gossiping 請求量（設計文件 4.2） |
| `crawled_at` | 爬蟲抓到該快照的時間（UTC），upsert 用它判斷新舊 |
| `unit_type`／`unit_key` | 警示的單位：`post`／`board`（之後 `entity`／`topic`）與其鍵值（設計文件 15.2） |
| 弱標註 | 用推噓比當標籤；已驗證不採用（設計文件 15.6） |
| shadow 比較 | 新模型與現行模型同時推論、只記錄不上線，比較後再切換（設計文件 8.4） |
| DLQ | `dlq` topic：解不開或違反約定的壞訊息，人工檢查 |
