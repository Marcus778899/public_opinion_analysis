## 3. 站規與停權風險（Q1）

- 條文：全站站規與 Gossiping／Stock／Tech_Job 板規都沒找到禁止自動化程式的條文；甲方沒有讀原文，內容是鏡像站轉述，所以是**未確認**，不是「沒有禁止」。細節與連結見 `docs/research/bbs-rules.md`。
- 唯一相關：SYSOP 2026-08-24 公告，稱「許多連線APP因自動連續登入連線，反而會被目前測試之功能阻斷登入」，自動連續登入有被阻斷的風險。第三方轉述稱短時間多次重連可能被當異常而暫時鎖定（可信度低）。
- 實驗中：登入共 2 次（P0 一次、P1＋P2 一次，間隔約 13 分鐘），皆成功；沒有警告、沒有觸發立即停止；小號沒有被停權（甲方回報）。2 次登入不足以推論長時間常駐的風險。
- IP（影響評估）：
  - 事實：家用網路，與開發環境爬蟲同一台機器、同一個對外 IP；沒有用手機網路分開。
  - 觀察：同一個 IP 上 BBS 登入 2 次都成功、未觸發立即停止；BBS 連線期間（04:01～04:42 UTC）網頁版讀取沒有失敗。唯一 1 次 FetchError 在 BBS 登出約 9 分鐘後（04:51 UTC），時間不重疊，原因未查，與 BBS 的關係未驗證。開發環境爬蟲本身有無錯誤，未驗證（不在本單資料來源）。
  - 評估：2 次登入、約 41 分鐘的量沒有看到 IP 被連帶影響，但不代表長時間常駐安全：SYSOP 公告的阻斷範圍是帳號還是 IP 查不到。共用 IP 一旦被封，網頁版爬蟲（主要資料來源）會跟著停（開發規格 8.1 風險表）。
- 若導入，BBS 服務與網頁版爬蟲應分開對外 IP，避免 BBS 被封時整條管線一起斷。這需要另一個出口（第二條線路、另一台主機或 proxy），屬決策分級②，雲端出口也要先驗（Q6），由甲方在導入時決定。分開 IP 只是隔離影響，不是被封後換 IP 繼續連；被封或觸發立即停止時一律停止（換 IP 繞過屬④）。
