#### M-1（medium）`ae import write --from` 在 sandbox 外讀任意路徑，可繞過「不可讀 `.env`」

**位置**（路徑相對於工具 repo `a46bcfc`，設定檔相對於本專案）

- `lib/agent_engineering/importer.py:285`：`draft = (ROOT / source).resolve()`，來源路徑沒有範圍限制；絕對路徑和 `../` 都有效
- `importer.py:288`：直接讀檔；`:294-297` 只檢查目的地；`:302` 把內容寫進目的地。`:303` 的 `is_relative_to(DRAFTS…)` 只決定要不要刪草稿，不會擋下來源
- `.claude/settings.json:30`（`Bash(ae import write:*)` 不經詢問就放行）、`:69`（`ae import *` 不受 sandbox 限制）

**攻擊情境**

1. 誰：importer，或沒有 `agent_type` 的 session（`guard_bash.py:14`、`:208-209` 不限制角色）裡的 agent，讀到夾帶 prompt injection 的內容。importer 的工作就是逐份讀專案原有的 AI 設定；一般 session 可能讀到 PTT 文章、LLM 回應或 issue 內文。其他角色會被 `guard_bash.py:221-222` 擋下
2. 怎麼做：執行 `ae import write .claude/x --from .env`，不跳確認視窗。主目錄永遠在 develop，所以 `require_on_base()` 這一關會通過
3. 拿到什麼：`.env` 的所有 token（Telegram、Groq、PG、ClickHouse…）被複製到 `.claude/x`。這個路徑不符合 `Read(**/.env)`，也不在 sandbox 的讀取禁止清單裡，agent 可以直接讀，再透過放行的網域（例如 `api.telegram.org`、`slack.com`）送出。`.claude/x` 也沒有被 `.gitignore` 排除，可能被後續的 `git add` 帶進 commit。同樣的方式也能讀 sandbox 禁止讀取的其他檔案

**為什麼是這一版才有**：舊版的內容來自 stdin，`< .env` 由 shell 在 sandbox 裡開檔，會被擋下（`importer.py:282` 的註解也寫了重導向會留在 sandbox）。改成 `--from` 之後，讀檔的動作移到 sandbox 外的程序裡。工具的測試（`tests/test_importer.py`）只驗草稿目錄內的路徑，沒有驗來源超出範圍要拒絕。

**為什麼判 medium，不是 high**：這個路徑要先有 prompt injection，未授權者無法直接使用；它只影響本機開發環境，不影響產品；而且同一個環境已經有能力相同、風險已被接受的 `docker compose *`（v0.6.0 M-3、D-011），這條路沒有讓攻擊者多拿到新的能力。不過 D-011 接受的是 docker compose 這一條，**不涵蓋這條新路徑**，所以仍列為發現。
