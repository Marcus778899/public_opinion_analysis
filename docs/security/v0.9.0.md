## 發現

### L-1（low）`PTT_BBS_*` 會被注入所有 app 容器的環境變數

- **位置**：`infra/docker-compose.yaml:32-37`（`x-app` 的 `env_file: ../.env`，`api`、`scheduler`、`crawler`、`ingest`、`cdc-watchdog`、`inference`、`inference-shadow`、`heat`、`bot`、`label-stream` 都繼承）、`:153`（`init`）；`.env.example:165-167`；D-046
- **攻擊情境**：甲方照 D-046 把小號帳密填進 `.env`，之後 `docker compose --profile app up`。Compose 會把 `env_file` 的每個變數放進容器環境（context7 查 Docker Compose 文件確認）。誰：已經能在任一 app 容器執行程式碼的人（例如經由對外的 `bot`、`api` 或其相依套件的漏洞），或主機上能跑 `docker inspect`／`docker compose config` 的人。怎麼做：讀 `/proc/1/environ` 或 `docker inspect`。拿到什麼：PTT 小號的帳號與密碼，這些服務根本用不到。開發規格 7.31 的威脅表寫「程式不進 compose」，但帳密實際上仍經由共用 `.env` 進了 compose
- **為什麼是 low**：要先攻破容器或有主機權限；同一批容器本來就有 PG、Telegram 等價值更高的 token（D-011 已接受主機端 `docker compose` 的風險）；小號是一次性的專用帳號。不過 D-046 讓這兩個變數變成常駐必填，實驗結束後仍會留在每個容器裡
- **修法**（擇一）：實驗已結束（`docs/reports/bbs-spike.md:44`），甲方清空 `.env` 的兩個值、改小號密碼，並依 D-046 的「之後不再做 BBS 時另議」把變數移回註解；若之後要導入，帳密改放獨立檔（例如 `.env.bbs`，`uv run --env-file .env.bbs`），或在 compose 的 `x-app` 用 `environment` 覆寫成空值，不要經由共用 `.env` 帶進所有服務
