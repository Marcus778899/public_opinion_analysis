## 發現

### F-1 匯入錯誤訊息兩處措辭可再順一點（minor，文案）
- 重現：1. `uv run --env-file .env python -m radar.ml.training.import_model --zip <有效 zip> --sha256 deadbeef`　2. 用內容不合格的 zip 帶正確 sha256 再跑一次
- 實際：
  - `error: 整包 zip 的 sha256 不符（實際 063ea89e…），請重新下載；不要把 --sha256 改填實際值`。同一行先印出實際值、又叫人不要填，容易讓人猶豫；而且錯誤之前還有一行英文格式的 INFO：`[2026-11-04 18:37:01]-INFO-(import_model|radar.ml.training.import_model.main:133)=> package sha256 …`，同一個值印兩次
  - `…不是合格的模型包（zip 內檔案必須恰為 ['model.onnx', 'model_card.json', 'tokenizer.json']），…` 中括號與引號是 Python list 原樣印出
- 預期：看得懂即可，不影響功能；建議把清單寫成「model.onnx、model_card.json、tokenizer.json」，sha256 不符只保留一處實際值
- 截圖：無（終端機輸出）

### F-2 全新環境只跑 `make up` 時 connect 會一直 unhealthy，`--wait` 失敗（minor，已知限制）
- 重現：Makefile `up` 目標（`$(COMPOSE) up -d --wait`，說明「啟動基礎設施」）沒有 `--profile app`，沒有 `init` 建立 connector
- 實際：依開發規格 7.30 B「已知限制」，connect 健康檢查要求 `radar-cdc` 存在，沒有 init 時 start_period（300 秒）後 unhealthy，`up --wait` 回非 0。我沒有實跑（會動到開發環境）
- 預期：README 與 Makefile 的 `up` 說明未提這個限制；README 只教帶 `--profile app` 的指令所以照做沒問題，只有直接用 `make up` 的人會遇到
- 建議：在 `Makefile` 的 `up` 註解或 README 補一句，或讓 `make up` 帶 `--profile app`
- 截圖：無
