## 發現

blocker 0、major 1、minor 2。

### F-1 e2e 的「停止並刪除 e2e 專用 volume」會連開發環境的 Grafana volume 一起刪掉（major）
- 重現：1. 開發環境運作中，Grafana 已啟動。2. README e2e 第 1 步停掉開發環境。3. 第 2 步啟動 e2e（e2e 也會起一個 grafana）。4. 第 4 步 `docker compose -f infra/docker-compose.yaml -f infra/docker-compose.e2e.yaml --env-file .env --profile app down -v --remove-orphans`。
- 實際：輸出中
  ```
  Volume radar_e2e_clickhouse_data  Removing
  Volume radar_grafana_data  Removing
  ...
  Volume radar_grafana_data  Removed
  ```
  e2e 的 volume 都有 `radar_e2e_` 前綴，唯獨 `radar_grafana_data` 與開發環境共用同名。我在第 4 步之後重建開發環境，Grafana 是全新的（`Volume radar_grafana_data  Creating`）。
- 影響：README 與 Makefile 都承諾「不碰開發資料」。目前 Grafana 的狀態只有 provisioning 載入的東西（dashboard 由 JSON 管理，7.25）加上甲方可能在 UI 做的個人設定（改密碼、偏好、星號），所以損失小，但之後如果在 Grafana 放了不可重建的東西（例如 alert、手動加的 dashboard）就會被 e2e 清掉。屬規則被違反，所以列 major。
- 預期：e2e 版 compose 給 `grafana_data` 專用名稱（例如 `radar_e2e_grafana_data`），或 e2e 不啟動 Grafana。
- 截圖：無（指令輸出）
