## 發現

### F-1 報告門檻 1 與 summary.json 的判定欄位說法不同（minor）
- 重現：1. 開 `data/spike/bbs/20261109T040131Z/summary.json`，看 `decision.latency` 2. 對照報告第 1 節門檻 1
- 實際：summary 寫 `"latency": true`、`p2.sample_ok: true`（183 則）；報告寫「部分證實」，因為扣掉不符選取規則的第 1 篇只剩 35 則。報告自己有說明原因，但用報告數字的人若只看 summary 會得到「延遲門檻成立」
- 預期：兩處說法一致，或報告註明 summary 的判定不看「發文 ≤ 1 小時」這條選取規則
- 影響：不改變「建議不導入」（連線門檻不成立）
- 截圖：無

### F-2 `--help` 對時間參數沒有說明與預設值（minor）
- 重現：`uv run python tools/bbs_spike.py run --help`
- 實際：`--p1-minutes`、`--p2-minutes`、`--tail-minutes`、`--run-id`、`--hot-concurrent-p90`、`--rules`、`--connections-proven` 都沒有說明文字，也看不到預設值（10／30／20、unconfirmed、1）；`--hot-concurrent-p90` 要從哪裡取得（`bbs-hot-articles-stat`）也沒寫
- 預期：說明列出單位、預設值、數值來源
- 影響：甲方得回頭翻 7.31 B；實驗已跑完，只在補實驗時有影響
- 截圖：無

### F-3 沒裝 bbs-spike group 的 `uv run` 會移除該 group 的套件（minor）
- 重現：先用 `--group bbs-spike` 跑過，再執行 `uv run python tools/bbs_spike.py --help` 或 `uv run pytest ...`
- 實際：輸出 `Uninstalled 2 packages` 與 `Installed 2 packages`（agent 本次執行即出現），也就是每次切換有無 `--group` 都會重新同步環境
- 預期：不影響結果；但補實驗時，`probe`／`run` 前務必保留 `--group bbs-spike`，否則 PyPtt 不在環境裡。7.31 B 的指令已寫對，這裡只是提醒
- 截圖：無

### F-4 `--out` 是全域選項，放在子命令後會被拒絕（minor，文件已寫）
- 說明：`--help` 的 usage 為 `bbs_spike.py [-h] [--out OUT] {probe,run,summarize}`，所以必須寫 `--out X probe ...`。7.31 B 有寫「要放在子命令前」，只是 `probe --help` 看不到 `--out`，使用者可能放錯位置。agent 未實際試錯（沒有跑會寫檔的命令）
- 截圖：無
