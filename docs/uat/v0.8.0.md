## 發現

blocker 0、major 1、minor 4。

### F-1 README 完全沒提階段 8：看不到怎麼匯入模型、啟動 shadow、跑 compare（major）
- 重現：1. 讀 README 全文，搜尋 shadow、BERT、import_model、compare、notebook。
- 實際：沒有任何一處。「功能」表停在 Dashboard（v0.7.0），「版本」表沒有 v0.8.0，「架構」表沒有 `notebooks/`。`make up-shadow` 只出現在 Makefile 的 `.PHONY` 與說明；步驟（匯出資料 → Colab → import → evaluate → shadow → compare）只在開發規格 7.27。第一次使用的人拿到這版不知道從哪開始。
- 影響：功能有但找不到入口，要讀 1000 多行的開發規格才能用，所以列 major。（若 README 預定在發版時才更新，請確認；目前 `main` 的發版前這是缺漏。）
- 預期：README 加一小節「BERT 與 shadow 比較」，列 7 個步驟的指令（docker 指令單獨一行），版本表加 v0.8.0。
- 截圖：無

### F-2 shadow 沒設模型版本時，容器不斷重啟且啟動指令仍顯示成功，錯誤訊息看不出原因（minor）
- 重現：1. `.env` 沒有 `INFERENCE_SHADOW_MODEL_VERSION`。2. 執行 `docker compose -f infra/docker-compose.yaml --env-file .env --profile app --profile shadow up -d --wait inference-shadow`。3. 看 `ps` 與 logs。
- 實際：指令輸出最後是 `Container radar_inference_shadow  Healthy`、結束碼正常；之後 `ps` 顯示 `Up Less than a second`（反覆重啟）；log 為 Python traceback，結尾
  `FileNotFoundError: [Errno 2] No such file or directory: '/app/models/model_card.json'`
- 預期：未設定時 `make up-shadow` 或服務啟動就印一句「請先在 .env 設 INFERENCE_SHADOW_MODEL_VERSION（models/ 下的資料夾名稱）」並停止，不進重啟迴圈。
- 影響：只要照 `.env.example` 設定就不會遇到；操作順序錯時使用者會被誤導以為成功，所以只列 minor。測試完我已 `stop` 並 `rm` 該容器。
- 截圖：無

### F-3 常見的輸入錯誤直接噴 Python traceback（minor）
- 重現：1. `uv run python -m radar.ml.training.import_model --zip <不存在的檔>`。2. 同上但檔案內容不是 zip。3. 匯入已匯入過的包。4. `evaluate --model models/nonexist`。
- 實際：1 為多層 traceback，結尾 `FileNotFoundError: [Errno 2] No such file or directory: '…/nonexist.zip'`；2 結尾 `ModelPackageError: not a valid zip file`；3 結尾 `ModelExistsError: …/models/bert-test-202610210000`（只有路徑，沒說「已存在、不覆寫，要重新匯入請先刪除或改名」）；4 結尾 `FileNotFoundError: … models/nonexist/model_card.json`。
- 預期：一行人話（「找不到檔案」「不是有效的模型包」「已存在，不會覆寫」「找不到模型資料夾」）並以非 0 結束碼離開，不印 traceback。內容正確（防呆有擋住），只是文案與呈現。
- 截圖：無

### F-4 三個命令列工具的 `--help` 缺參數說明（minor，文案）
- 重現：`import_model --help`、`compare --help`、`evaluate --help`。
- 實際：`--zip ZIP`、`--model MODEL`、`--since SINCE` 沒有說明文字；`compare` 只有 `--a`、`--b` 有（「現行版本（predictions）」「shadow 版本（predictions_shadow）」）。`--since` 必須是 ISO 格式（錯誤訊息 `invalid fromisoformat value`），help 沒給範例，也沒說是否視為 UTC。
- 預期：每個參數一句說明；`--since` 給範例（例如 `2026-10-26T00:00:00+00:00`）並註明時區。
- 截圖：無

### F-5 `evaluate`、`compare` 缺環境設定時只丟 pydantic 驗證錯誤（minor）
- 重現：在沒載入 `.env` 的 shell 執行 `uv run python -m radar.ml.training.evaluate --model <模型資料夾>`。
- 實際：traceback 結尾
  ```
  pydantic_core._pydantic_core.ValidationError: 2 validation errors for ClickHouseSettings
  user  Field required
  password  Field required
  ```
  Makefile 其他目標用 `uv run --env-file .env`，但 README／開發規格寫的是直接 `python -m …`，使用者不知道要自己帶 `.env`。
- 預期：文件寫明指令前綴（例如 `uv run --env-file .env python -m …`），或程式把這種錯誤轉成「請設定 CLICKHOUSE_USER／CLICKHOUSE_PASSWORD」。
- 截圖：無
