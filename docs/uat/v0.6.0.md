### F-1 README 的 `make seed` 與 Makefile、開發規格對前置條件說法矛盾（minor）
- 重現：1. 讀 README 快速開始第 4 步：「建立看板：`make seed`」，前一步已用 docker 啟動 api。2. 讀 `Makefile` 第 53 行：`seed:  ## 透過 API 建立初始看板（需先 make api）`；開發規格 1.3 同樣寫「需先 `make api`」。
- 實際：照 README 做，API 已在容器內，不需要 `make api`；Makefile 與規格卻要求先在本機再起一個 API（port 8000 會衝突）。第一次使用的人不知道該不該執行 `make api`。
- 預期：Makefile 與規格註明「docker 已啟動 api 時不需要」。
- 截圖：無

### F-2 README 沒說 `TELEGRAM_ALLOWED_CHAT_IDS` 留空等於任何人都能用這個 bot（minor，文件）
- 重現：1. 讀 README 步驟 1：只提到 `.env` 需要 `TELEGRAM_BOT_TOKEN`。2. `.env.example`：`TELEGRAM_ALLOWED_CHAT_IDS=` 註解「留空代表不限制」；`src/radar/bot/main.py` 的 `is_allowed` 空清單回傳 True。
- 實際：只照 README 設定 token 的使用者，bot 會對知道 bot 帳號的任何人回應，包含訂閱與看到警示內容。
- 預期：README 步驟 1 提示要填自己的 chat id，或說明留空的後果。此屬安全／權限類，是否改預設為拒絕建議交 manager 評估是否開 D-編號。
- 截圖：無

### F-3 `radar_init` 容器結束碼 255，從外面看不出是否正常（minor）
- 重現：1. `docker compose -f infra/docker-compose.yaml --env-file .env ps -a`。2. 看到 `radar_init Exited (255)`，而 `radar_apicurio_db_init` 為 `Exited (0)`。
