## 發現

blocker 0、major 0、minor 4。

### F-1 README 的 `make seed` 與 Makefile、開發規格對前置條件說法矛盾（minor）
- 重現：1. 讀 README 快速開始第 4 步：「建立看板：`make seed`」，前一步已用 docker 啟動 api。2. 讀 `Makefile` 第 53 行：`seed:  ## 透過 API 建立初始看板（需先 make api）`；開發規格 1.3 同樣寫「需先 `make api`」。
- 實際：照 README 做，API 已在容器內，不需要 `make api`；Makefile 與規格卻要求先在本機再起一個 API（port 8000 會衝突）。第一次使用的人不知道該不該執行 `make api`。
- 預期：Makefile 與規格註明「docker 已啟動 api 時不需要」。
- 截圖：無

### F-2 README 沒說 `TELEGRAM_ALLOWED_CHAT_IDS` 留空等於任何人都能用這個 bot（minor，文件）
- 重現：1. 讀 README 步驟 1：只提到 `.env` 需要 `TELEGRAM_BOT_TOKEN`。2. `.env.example`：`TELEGRAM_ALLOWED_CHAT_IDS=` 註解「留空代表不限制」；`src/radar/bot/main.py` 的 `is_allowed` 空清單回傳 True。
- 實際：只照 README 設定 token 的使用者，bot 會對知道 bot 帳號的任何人回應，包含訂閱與看到警示內容。
- 預期：README 步驟 1 提示要填自己的 chat id，或說明留空的後果。此屬安全／權限類，是否改預設為拒絕建議交 manager 評估是否開 D-編號。
- 截圖：無

### F-3 `radar_init` 容器結束碼 255，從外面看不出是否正常（minor）
- 重現：1. `docker compose -f infra/docker-compose.yaml --env-file .env ps -a`。2. 看到 `radar_init Exited (255)`，而 `radar_apicurio_db_init` 為 `Exited (0)`。
- 實際：所有服務、資料表與 connector 都正常，推測是 11 小時前的某次啟動留下的紀錄，我無法取得該容器 log（sandbox 擋住，且 `logs init` 需要 profile）。使用者看到 255 會以為初始化失敗。
- 預期：一次性初始化容器成功時結束碼為 0；失敗原因可從 log 查到。請開發者確認 255 是否為已知現象（例如被重新啟動時中斷）。
- 截圖：無

### F-4 Telegram 長輪詢逾時時 bot 靠重試恢復，但連續 ConnectError 無對使用者的提示（minor）

## 甲方驗收清單

Telegram 需由甲方親手操作。測試前請確認 `.env` 的 `TELEGRAM_ALLOWED_CHAT_IDS` 含你的 chat id，且 bot 容器在跑（`docker compose … ps` 看 `radar_bot` 為 Up）。

主選單與畫面
- [ ] 對 bot 傳 `/start`：看到主選單，有 🔥 現在熱門、📋 我的訂閱、📈 看板概況、⚙️ 通知設定四個按鈕；文案通順、沒有亂碼或未轉義的 `<` `&`
- [ ] 傳 `/menu` 同樣顯示主選單；點輸入框旁的指令清單，能看到 bot 註冊的指令（`setMyCommands`）
- [ ] 在四個畫面之間來回切換：每次都是「編輯同一則訊息」，不會新增一堆訊息；每個畫面都有回主選單的方式
- [ ] 按鈕點下去後 2 秒內畫面更新，按鈕不會一直轉圈（連點 5 次各畫面計時）

訂閱
- [ ] 📋 我的訂閱：每個看板以 ✅／⬜ 表示狀態；點一個看板會切換狀態且同一則訊息更新、有短提示（如「已訂閱」）。全程不需要輸入看板名稱
- [ ] 切換訂閱後，「現在熱門」預設只列訂閱看板的文章；有切換「全部看板／只看訂閱」的按鈕，且兩種結果不同
- [ ] 取消全部訂閱後點「現在熱門」：改看全部看板（規格 7.23），畫面沒有出現空白或錯誤
- [ ] 重新整理：關掉 Telegram 再打開，再按舊訊息上的按鈕，仍可用；若出現「選單已過期」，會自動重送主選單

現在熱門與看板概況
- [ ] 🔥 現在熱門：最多 5 篇，每篇有標題、新增推文數；標題裡有特殊符號（< > &）也顯示正常；有連到原文的方式
- [ ] 📈 看板概況：選一個看板，看到近 24 小時文章數、新增推文數、情緒比例（寫明「n 篇有推論」）、爭議度最高的文章、今天的警示數；數字看起來合理，沒有 `None`、`NaN` 或空欄
- [ ] 選一個文章很少的看板（Boy-Girl、Tech_Job）的看板概況：沒有資料的欄位有合理文字，不出現錯誤

通知設定
- [ ] ⚙️ 通知設定：有「文章警示」與「看板警示」兩個開關，點了立即顯示新狀態
- [ ] 關閉「文章警示」後，下一次收到的只有看板警示（需等到真的有警示；若等不到，記錄為未驗證）
- [ ] 再打開後恢復收到文章警示

警示內容（等到真實警示，或請開發者重放暴增）
- [ ] 看板警示：顯示看板名、推文數與「平常的幾倍」、前 3 篇文章各自的推／噓／箭頭、爭議度、文章情緒；排版易讀

- [ ] 警示按鈕：每篇有「開啟原文」且能打開正確的 PTT 文章；有「看板概況」、「訂閱設定」；文章警示另有「這篇不再通知」，看板警示沒有此鈕
